B1 验收 · 一键提取当前页面

在任意页面点一下插件图标，右侧会开出面板并显示结果。这一页是这张验收单，样例页在同一个目录里。

  • 标准一　在所有样例站点上都能正常启动提取并展示结果，不报错
  • 标准二　提取过程不改变原页面的外观和功能
  • 标准三　在插件无法运行的页面上给出友好提示
动手之前先做四件事。
  1. 打开 chrome://extensions，找到 DESIGN.md Extractor，点卡片上的刷新图标，确认没有任何红色报错。
  2. 把扩展图标固定到工具栏。点地址栏右侧的拼图图标，找到它，点旁边的图钉。
  3. 这一页和所有样例页都是本地文件。需要在扩展详情页里打开「允许访问文件网址」，否则会看到一张提示页。没打开时提示页上有个按钮可以直接跳过去。
  4. 把窗口拉宽到 1440 上下。全部数值都是当前视口下的渲染计算值，窄窗口下响应式页面会换一套值，对不上是正常的。
样例页一律用新标签页打开，这样这张验收单还在，勾选不用来回切。
界面从弹窗换成了侧边栏（2026-10-13 起），走法有三点不同。
  1. 点图标之后结果出现在右侧面板里，不再是弹窗。面板不挡页面，也不随点击消失。
  2. 面板收起来再打开，上一次的结果还在，不用重新提取。但换到别的标签页想看那一页的风格， 要再点一次图标。
  3. 面板里没有提取按钮。这是 Chrome 的权限模型决定的，不是漏了：读取当前页的授权 只在点图标那一刻给出，在面板里点按钮拿不到它。所以提示页上那个「重新提取」按钮也没有了， 取而代之的是一句「点一下工具栏上的插件图标可以重试」。

S2无样式页信息量最低的一端
样例 s2-bare.html 打开

整页不写一行 CSS，全用浏览器默认样式。期望：

  • 正常出结果，不报错，也不出现覆盖范围警示
  • 页面底色是 白色
  • 色板里应当有浏览器默认的链接蓝 #0000ee

反向的验收点在这里：结果里如果冒出这一页根本不存在的颜色或字号，说明有地方在凭空造数， 那比缺东西严重得多。

S3只有渐变与图片背景背景通道退化
样例 s3-gradient.html 打开

整页没有一处纯色背景，全靠渐变和一张内联背景图。期望：

S4声明写法边界颜色与单位的写法
样例 s4-syntax.html 打开

同一个蓝色用七种写法写（三位缩写、八位、rgb 空格与斜杠、逗号、hsl），另外还有具名色、 变量、简写、单边、!important、内联覆盖、相对单位。期望：

S5可见性过滤哪些不该被算进去
样例 s5-visibility.html 打开

页面分三组。A 组是八种不可见的写法，各自一个全页唯一的颜色；B 组是两个正常可见的对照； C 组是三条如实记录的边界，不参与判定。期望：

  • A 组的八个颜色一个都不出现
  • B 组的蓝色 #2563eb 与橙色 #ea580c 都出现（没有这个对照， 「全都没出现」也可能只是因为整页采空了）

A 组里最值得盯的是收起的折叠区那一条。Chrome 对收起的 <details> 仍然会排版， 它的尺寸是真的，display、visibility、opacity 全是正常值， 只有可见性判据认得出它不可见。真实页面上对应折叠面板、抽屉、收起的菜单，里面往往是大段说明文字。

S6结构边界内容不在主文档树里
样例 s6-structure.html 打开

同一条边界上有四种情况，可读性完全不一样。期望：

  • 主文档里的对照青 #0891b2 出现
  • srcdoc 框架（同源）里的柠檬绿 #a3e635 应当出现，说明同源框架的内容被一并读了进来
  • 影子树里的紫 #8b5cf6 不该出现。这是一个已知缺口，当前实现没有任何提示， 用组件库搭的页面会有整片内容静默缺失
  • 画布上的红 #ff0000 与内联 SVG 的绿 #22c55e 都不该出现，这是设计如此
  • 出现一句 PDF 覆盖范围说明，指出内嵌的那处 PDF 不在色板覆盖范围内

同目录下的那个本地文件框架是个观察点。两种打开方式结果不同：用 file:// 直接打开时 Chrome 把每个本地文件当成独立来源，读不到；用 http 起本地服务器打开时属于同源，能读。两种都接受，但要知道自己看到的是哪一种。 跨域框架那一条需要联网，不联网时框架是空的，结论一样是读不到。

S7提取不改变原页面（自检页）标准二的载体
样例 s7-interactive.html 打开

这一页自带一个自检按钮，把「有没有被改动」变成几个数。按页面上写的顺序走：先改点状态， 点「记下基线」，点插件提取，回来点「自检并比对」，表格每一项都应当是绿色的一致。 比对的是 DOM 元素数、带 style 属性的元素数、滚动位置、计数器、输入框内容、静默区被改动次数、三个关键元素的位置与尺寸。

这一条在自动检查里已经用真实浏览器验过一遍：八个样例页在采集前后， DOM 节点数、带 style 属性的元素数、body 与 html 上的 style 属性全部逐字节相同。 人工走这一遍是为了确认脚本没覆盖到的部分，比如面板开关之后页面的交互状态。

S8极端形态与体量量最大的一端
样例 s8-extremes.html 打开

页面上有九千多个元素，还有四百层嵌套、120px 与 9px 的字号两端、横向溢出的宽元素、 从右往左的段落、emoji 与组合字符。期望：

  • 统计行里出现一句 「页面过大，只采集了前 8000 个元素」。 静默截断是最坏的做法，用户会拿一份残缺的色板当完整的用

上面的样例都是我们自己写的，容易「刚好都长得像工具认识的样子」。再拿几个真实站点各点一次图标， 只要都能出结果、不报错就算过，具体数字对不对是后面几条验收线的事。

二标准二 · 提取不改变原页面的外观和功能

V1外观不变

在 S1 上截一张图，点图标提取，收起面板，再截一张。两张应当完全一样， 不该出现位移、跳动、多出来的描边或底色。高亮那条验收线会主动往页面上画描边， 但那是用户点了 token 之后才有的事，单纯提取不该在页面上留下任何东西。

V2功能不变

在 S7 上先把状态改掉（点几下加号、输入几个字、选好下拉项），提取之后再操作一遍。 按钮还能点、计数器接着走、输入框内容还在、折叠区还能展开、那个方块还在动。 页面上原有的事件没有被打断或吞掉。

V3滚动与焦点

在一个长页面上（S7 或 S8，也可以拿 MDN 那种长文档），先滚到页面中间， 提取之后再回来。滚动位置不该被重置到顶部，输入焦点也不该被抢走。

V4控制台无报错

在样例页上打开 DevTools 控制台，先看一遍基线，再点图标提取，再看一遍。 两边都不该多出红色报错。有报错就说明注入在页面上留下了痕迹，哪怕是没被看见的那部分。

四面板形态 · 内容只认当前页，可折叠

这三条只有真机能验：侧边栏是浏览器自己的界面，脚本点不到。开始之前先在 chrome://extensions 里重载一次扩展，构建会重建整个输出目录，不重载的话点图标同样没反应。

M1面板只显示属于这一页的结果作用域

在样例页上点图标出结果，然后做三件事。一，切到一个从没点过插件的标签页，在那里点一次图标：图标必须能点、面板必须打开。这一条是回归验证，之前有一版图标会变灰点不动，整套功能静默失效。二，看那个页面上的面板，内容应当是「还没有提取过」，而不是继续显示样例页的数字。三，切回样例页，面板内容应当变回样例页的结果。

面板本身不会跟着页面消失。这是 Chrome 的二选一：要让侧边栏在某页不存在，唯一机制是禁用该页的侧边栏，而禁用会让那一页的插件图标一起变灰、点不动。两个要求互斥，这里保住的是「任何页面都能点图标开始提取」。第一条如果过不了，说明又退回了那个禁用写法。

M2折叠成窄条与展开面板内折叠

点头部那个小三角，面板内容应当收成左侧一条 44px 的窄栏，栏上有一个反向三角和竖排的页面名；点窄栏上的三角，应当展开回完整界面。折叠之后切到别的标签页再切回来，面板重建之后应当还是窄栏，不是又弹成一整屏。

面板本身的宽不会变，Chrome 不给扩展控制宽度的接口，所以窄栏右边会留一片空白，那不是 bug 是 Chrome 的地板。要连面板一起收走，用下一个用例的关闭按钮。

M3关闭面板和折叠是两回事

点头部的 ✕，整个面板应当消失，页面占回原来那 320px。之后想再看结果，再点一次插件图标即可，上一次的结果会直接显示出来，不用重新等采集。
